# 人工走读范围与结论

阅读对象是两份输入包和统一后的有效正文/配套合同，不是用户最新本地源码。源码旧基线只用于定位可复用层；本轮没有拿它当本地完成进度。

| 路径 | 逐段核对的问题 | 对齐位置 |
|---|---|---|
| 新Session→初始L1→准备实例 | bootstrap只加载固定A；Branch与active指针最终激活；ready不等可发布 | 01/02步骤10/05 TX-S1/S2/SQL |
| 用户Task→私有SUBMIT→Core | public不授予权限；Q/L/epoch/digest/status冻结；重复受理不再启动 | 02步骤1/3/6/11/Schema/reference |
| steer/cancel与STOP | 同Control锁裁决；控制请求不排长任务后；持久化失败不伪装答案 | 02步骤3/6/7/05 |
| Task结束→下次Task | 本地Finalizer不发布；未决平台操作保留原ID；旧事件不清新槽 | 02步骤8/11/08 |
| report_progress→Branch | immutable PROGRESS；固定元数据；CAS/op/outbox同事务；取消不是undo | 08/05 TX-P/13/15 |
| dirty W时merge | 不读W/checkpoint；无active/pending/sync；S/T/R最终校验；Q继续/L已合并 | 02步骤15/12/13/ManagedBranchPolicy |
| 同Q显式同步 | B/H/W移植；DISCARD具体确认；备份先于替换；new ready后激活 | 12/sync-recovery-table/SQL |
| 旧实例与新context | epoch不复用；oldPARKED不可派发；原历史保持hash；切线事实不提前 | 05/09/12/19/context-handover |
| PR版本/讨论 | 版本历史不冒充当前HEAD；固定行锚点；close旧请求不关闭后来reopen | 13/16/Mapper |
| 社交/通知/Feed | 关系影响行数；当前ACL先过滤；receipt与投影同事务；失败持久化后ACK | 14/15/16/SQL |

审查修正了audit/修正登记中的22个明确问题/遗漏。人工走读不构成穷尽并发证明；外部调用仍需真实故障注入。文件存在/编译/关键词扫描也不能证明业务实现正确。发现新冲突时必须同时改正文和类型/SQL/fixture，不重新采用“某补丁优先”的习惯。

剩余的不确定项明确限定：用户当前库类型与已执行迁移、实际API依赖版本与SDK兼容、真实文件系统/网络/并发行为、资源上限、低推理模型和初学者实用性。它们记录为待验证，不留作“你自己决定到底什么架构”的暗洞。
