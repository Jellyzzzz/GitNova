## 结论

**施工层已经补齐到可以开始按步骤手写的粒度；不再只是架构方向与功能清单。** 文档现在给出了源码路径、首次编写步骤、关键方法/字段、算法顺序、接口参考、数据库DDL、SDK接线样例、测试入口及旧代码退役条件。

但是，“文档静态闭合”与“已在你的最新代码和部署环境中从0走到1”是两种证据。本次没有你的完整未提交源码，也没有可用Docker、Maven依赖下载或MySQL。不能承诺整个重构已真实构建验证，更不能把尚未执行的104项产品验收写成通过。该限制不隐藏在脚注里：步骤0做实际源码对齐，步骤9做供应商环境接线，步骤10以后做真实数据库和平台联调，步骤18做完整验收。

## 2. 这次自检确实发现并修复的设计接缝

**施工顺序悬空。** 旧步骤要求先创建/初始化Sandbox，却把Worker初始化包处理和封存实现放在后面。现已将Worker初始化与真实封存装配放到步骤8，OpenSandbox接线为9，平台Session为10，任务/事件/归档为11。无DB的AgentWorkerClient提前至9；RepositoryBootstrapService与CommitTreeService读取能力在10先写，Session不再依赖尚未出现的归档服务。

**HTTP依赖后面的具体实现。** 增加WorkerResources和TaskFinalizer接口，使控制层可以先测试；生产装配必须在步骤8接入真实实现。测试替身不进入正式Worker JAR。

**接口名称互相冲突。** 统一AgentEngine三参数签名、ToolRuntime本地Map类、ContextCoordinator接口与DefaultContextCoordinator实现；删除旧EventSink/LocalToolContext缩写残留；统一Mapper注解SQL，不同时要求一套XML。

**物理目录与示意图不一致。** 镜像和手册统一到`/session/worktree`、`/session/state`、`/session/baseline`等目录；不依赖未建立的/workspace符号链接。运行配置JSON成为明确启动输入，不等待尚未ready的Worker反向取配置。

**旧Task表无法承载新状态。** 旧agent_task/agent_run保持历史约束，新任务写独立控制表；没有用修改旧CHECK来掩盖新旧执行语义冲突。

**SSE归档的offset迟提交风险。** 同Session先锁行再分配archiveOffset，事件与投影/cursor同事务，不因AUTO_INCREMENT先分配后提交而漏页面事件。

**CANCEL与不明SUBMIT竞态。** 区分未发送、已发送和结果未知；取消404不能作为另一请求未执行的证明；同commandId重发不创建新attempt。

**封存包没有后来的ACK。** 归档持久保存平台结算附记。恢复旧包时补正确publishedHead和baseline；不会恢复到已经被发布结果淘汰的HEAD。

**tracked集合固定在最初A。** 成功发布后baseline更新，后续ignore不会把已经发布的新增文件误删；SKIP保留旧基准与未发布修改。

**PR和Agent发布竞态。** merge前检查关联Session空闲、已结算，固定双HEAD与PR revision；受管目标分支也检查，不能让合并和Agent同时写。

**旧能力误退役。** 已启用Review必须先适配到新执行体系；CODING仍无finishTask，Review结构化报告不是全体任务的终止协议。未实现的旧stub不被写成已迁移工作功能。

**依赖基线不确定。** SDK按固定tag核对，避开已知缺包wheel的安装路径；明确保留源码构建和实机探针门槛，不将“看过API”写成“实际接通”。
