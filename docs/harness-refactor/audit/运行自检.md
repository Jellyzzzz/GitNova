# 运行文档自检

需求：Python 3.11+、JDK21（javac/java）；Python环境含jsonschema和rfc3339-validator。requirements-audit.txt记录本轮实际使用版本，仅用于文档验证，不加入GitNova生产依赖。缺包时在独立虚拟环境安装；离线机器可先准备wheel，不让导入脚本联网安装。

在包根执行：
```bash
python3 scripts/self_check.py
```

输出audit/check-results.json，26个检查组分别标STATIC/CONTRACT/REFERENCE/SPEC_MODEL/PROBE/READABILITY_STATIC/ENVIRONMENT。第一次运行可能需要约一分钟；任何FAIL先看具体group/detail。不因为工具不存在就把MySQL/Docker列通过，环境检查只报告安装情况。

12个Python规格模型测试是用于反例检查的独立小模型，不是生产业务实现。ScopeProbe/ConfigProbe测试包内纯参考代码；TransportProbe和process-launch探针只测当前Linux/本机HTTP，不测OpenSandbox或用户的Java进程管理器。

contracts/acceptance.json当前全NOT_RUN。实际实现后可填PASS，但evidence至少含commit/command/artifact；自检不会为你执行全部产品用例，也不会自动改状态。日后修改SQL/reference/Schema时重新跑；单词扫描只能发现已知坏模式，不能代替人工审查。

导入演练的仓库是脚本创建的临时目录；验证dry-run不写、--apply外部备份、只替换docs、src保留。真正使用仍先查看git status及dry-run目标；对含symlink的旧docs明确拒绝自动替换，不猜用户目录布局。
