# 源码迁移与包文件地图

这是施工坐标，不是“按名字删除”的脚本。旧基线是 `316112ae38747a5f5ceef95aa6e6b095fa76c919`；本地未提交的自然 STOP 与查询变更以用户已给出的行为为准。完整文件内容并未在本环境编译运行。

## 1. 根目录和新包的唯一规则

保留根 `pom.xml` 和 `src/` 为 Server。新增 `agent-runtime/pom.xml` 聚合新模块。protocol=Java17，core/worker=Java21。不要把根Boot项目改成聚合父工程。

```text
agent-runtime/
  agent-protocol/src/main/java/com/gitnova/agent/protocol/
    command/ event/ query/ snapshot/ transport/ json/
  agent-core/src/main/java/com/gitnova/agent/core/
    config/ engine/ model/ context/ history/ tool/ process/
  agent-worker/src/main/java/com/gitnova/agent/worker/
    control/ http/ seal/
src/main/java/com/gitnova/
  service/agent/control/       # 平台控制，不放AgentLoop
  service/repository/          # 共用Commit/Branch能力
  service/pullrequest/
  mapper/agent/control/
  entity/agent/control/
src/main/resources/static/agent-ui/  # 新功能独立模块；旧页面通过mount接入
```

新包是本次设计决定；不是假定旧仓库已经有这些目录。测试放同模块 `src/test/java`，包与被测类相同。本次选择Mapper注解SQL，不新增XML目录；完整方法与SQL在contracts/mapper-contracts.md。

## 4. 六个必须逐方法切开的接缝

### AgentRuntime → DefaultAgentEngine

`run` 保留请求构建、模型计数、tool id配对、结果/反馈进入下一轮；注入的旧WorkspaceGateway、RunJournalScope、CompletionInspector、平台ExecutionConfig和lease路径不迁移。ContextAssembler不整体复制，而是替换history接口后迁算法。旧 `handleFinish` 仅旧历史兼容。用户本地 `handleNaturalStop` 的“响应先落库/有效正文/确认后回答”语义转为本地log，不保留全树drift作为每次循环前置条件；替代前提是平台不修改活动树、单Worker和受管理进程。对比测试必须覆盖这一替代前提。

### SessionContextService → SessionHistoryReader

先迁 `load` 中对tool/assistant配对、summary覆盖、through边界和usage anchor的处理；替换 `AgentStepEntity` 为 AgentEvent；将Mapper分页改成本地log索引分页。使用协议提供者的原始reasoning字段供下次模型请求所需，不经公共UI输出。旧源码的STRICT连续sequence只在单epoch内部成立，跨epoch活动历史按恢复选择器而非简单seq拼接。

### ArtifactTextReader → HistoryIndex + HistoryRead/Search

原始结果读取、结果内范围读取、Session集合检索三件事分开。文件bytes从ResultStore取；sourceEventId保留历史task/epoch。查询固定through和cursor语义。不能把history工具删掉，期待模型自己猜state目录位置。小结果照样获得source身份，但不用为每个小结果复制三份物理文件。

### ToolRegistry → ToolRuntime

Map注册、名称冲突、schema、字段错误反馈保留。当前普通Spring调用不是每一步真实RPC，不夸大原架构；删除的是对平台权限/Workspace持久协调的执行依赖。新Runtime依然需要Tool协议，减少的是基础设施参数，不是取消模型函数调用。

### AgentSessionService → SessionLifecycleService

保留“短事务记录准备→事务外环境创建→短事务激活”。删除WorkspaceProvider/Registry；固定Commit A仍调用RepositoryRevisionService。branch创建与激活在同一短事务。Sandbox create超时不能依靠DB回滚撤销远端副作用，要靠createOperationId标签核对。

### TransferService → BranchPublicationService + CommitTreeService

先用原push回归测试锁住合同，再提取private校验方法。对象写入在事务外，branch visibility在DB CAS事务。保留default branch缓存/CommitRecord/事件。严禁把agent branch直接当main更新，严禁拿commit_record.branch_name过滤祖先链代替真实commit图。

## 5. 自动 Review、suggest-message、chat 不能“顺手删掉”

这三条旧入口在基线目录中存在；它们的真实上线程度需本地baseline确认。对已经工作的自动Review，步骤 17必须先写适配：`CodeReviewListener`收到旧PostReceive之后创建 `delivery=NOT_REQUIRED` 的REVIEW任务，输入固定base/target和比较清单；同一个Worker执行，不再调用服务端旧Loop。Review专属structured finding解析与原ReviewVerifier保持在结果适配层，失败标“审查结果不可解析”而不是假成功。可在专属review提示中要求结构化内容，但不能强迫所有coding任务恢复finishTask JSON。

原 `ReviewComment` 表继续供旧结果读；新review适配将验证后的结构化findings映射到该表，带原target commit。`FinalizeReviewTool`只有专属旧调用存在时才保留只读解码，不进入新coding工具列表。若旧接口本来是TODO，记录为旧未实现，不说此次删除了工作功能。`suggest-message`一次模型调用可以仍留平台，不算保留服务端AgentLoop；`chat`已实现则适配到Worker问答，并维持公开响应形状。这些必须有调用方回归测试。

## 6. 本地差异与退役门槛

运行 `scripts/inventory_current.py /你的/GitNova`，它只读扫描.java/import，输出文件hash、已知映射、额外本地文件和自然STOP锚点；不会上传源代码，也不会自动删文件。出现UNKNOWN新增文件，就先映射其职责再退役，不能套用旧目录清单。反射、XML bean、配置字符串和前端调用还需全仓库文本检查与构建证明，脚本不是完整Java依赖分析器。

删除门槛：新同等行为测试通过；调用方已改接；生产活动任务已收口；旧历史仍可读；打包启动不创建旧线程或物化工作树。只要一项没过，就不能删。最终保留的是只读兼容，不是两个可执行引擎。

### 辅助类型放哪里，避免边写边猜

`HistoryIndex.ResultRecord/SearchQuery/SearchPage`、`FileResultStore.CaptureImpl`、`LocalShellTool.Args`、`SafePaths.Conflict`均作为所属类的public/static record或私有辅助类型，不再单独建包。`ContextTypes`提供HistorySnapshot/Group/Summary/Measurement；`ModelTypes`提供Message/Request/Response/ToolCall/ToolDefinition/Usage。跨Server边界的LaunchSpec/Binding/VerifiedBundle等记录统一放`ControlTypes.java`（service.agent.control包）；PR请求/响应记录作为PullRequestController的嵌套record。DTO中日期用Instant，外部参数先解析再传入Service，SQL行不直接发给Worker。
