# Pi 风格摘要提示词：真实 API 准确性验证

## 结论

2026-09-20，完成 6 次真实摘要调用。全部通过生产 ContextSummarizer 的协议校验：STOP、无工具调用、非空正文；没有超时、截断或重试。
**调用成功不等于内容全部准确。新提示词有局部改善，但不能宣称已解决摘要失真。**

可保留新提示词作为当前默认；后续最值得处理的是引用/关键证据的确定性保留，而不是不断追加提示词。
本轮不增加 Run 最终状态投影，也不以缺少 Run 最终状态作为摘要错误判据。

## 测试方法与边界

- 固定历史：上一次真实多 Task 实验的 C/D 测试仓库记录。
- 复用生产 SessionContextService 和 ContextSummarizer，在内存中重放已导出的 Steps。Mapper 用测试替身；没有连接或修改数据库。
- C 首次摘要覆盖至 sequence 34；D 首次摘要至 48。两份历史分别用旧提示词、新提示词各调用一次，历史正文 SHA-256 相同。
- C/D 增量摘要分别覆盖至 67/111；输入为档案中的原始旧摘要 + 后续真实记录，不是本轮刚生成的新摘要。不人工修正旧错误，旨在检查旧信息能否被可靠更新。
- 所以增量样本测试的是“旧格式摘要迁移/更新”，**不是新提示词连续多次滚动的长期稳定性测试**。
- DeepSeek 模型由运行时配置，实际模型见 results.json；thinking disabled，temperature 未指定，与生产摘要请求一致。
- 6 次调用统一 maxOutputTokens=4096、callTimeout=60 秒、readTimeout=60 秒；输入预算本地预检通过；无工具执行。
- 旧 prompt 使用 summary-prompt-before.txt；新 prompt 使用编译后的生产实现。没有在实验中途修改提示词或重跑失败样本。
- SQL 导出不含 eventId，回放只重建 Mapper 因果关联键；进入模型的 payload 保持原样。

这验证的是固定历史上的摘要生成，不是新一轮 HTTP → Worker → 工具执行的端到端测试。

## 内容核对

### 首次摘要：有改善，也有遗漏

- C 新旧摘要均保留了两个缺陷根因、修复方案、当前任务授权范围与 7 条失败订单的 expected/actual total。
- C 新摘要遗漏了原始 `BATCH SUMMARY cases=160 passed=153 failed=7` 汇总行，但保留了 7 条失败明细与修复后 `160/160/0`。这是**信息遗漏，不是把 failed=7 改成 failed=0**。旧摘要保留了两条完整汇总。
- D 旧摘要未保留两个完整 Artifact ID；D 新摘要保留了 **2/2**，与输入逐字匹配，未缩写或编造。
- D 新摘要保留了修复前 `160/153/7`、修复后 `160/160/0`、原始失败行与两处源码修复。
- D 新摘要另有小事实错误：称 generation 1 是“两次 applyPatch 后”；该输入实际只有一次 applyPatch 调用，批次内修改两个文件。不能把 operation 数量等同于 Tool Call 数量。

### 增量摘要：仍会传播旧摘要的损失

- C 保留了当前审核任务的只读约束、尚未落地的边界测试、历史通过结果；未把“边界测试计划”说成已经执行。
- C 没有继续输出旧摘要的错误算式 `100×50/100=50.5`，而是保留正确案例数据。这只能说明错误算式未再出现，不证明具备通用算式纠错能力。
- C 仍沿用了旧摘要中的四个缩写文件哈希：`5413bca6...` 等。该增量输入没有完整哈希，模型不能凭空恢复；正确做法应是省略不可用引用或明确标记不完整，而非当成文件标识继续列出。
- C 将浅层根目录列表作为“src 下不存在 EdgeRegression”的证据，引用不充分。实际列表只包含 README、fixtures、run-tests.sh、src；不是递归源码树。该文件实际未新增，但不能把结论恰好正确当成引用准确。
- C 还将读取 run-tests.sh 的来源标为 sequence 56；实际在 HISTORY 52..54，56 不在输入的任何 HISTORY 范围内。引用完整不代表引用指向正确。
- D 保留了已新增 16 项边界测试、完整链路通过、故意改坏预期得到 `failed=1 / exit=1`，并正确将后者描述为失败路径验证，不是当前回归失败。
- D 保留了 applyPatch 的部分成功与 generation 1→2→3，没有抹掉先成功的 CREATE，也没有把已解决的补丁失败写成当前阻碍。
- D 保留了后续输入中的 **3/3** 完整 Artifact ID，但仍沿用旧摘要中的 `5cdce…` / `d2e9…`；这两个旧完整 ID 已不在该增量输入中，提示词无法无损重建。

### 格式与引用检查

- 新提示词 4 个样本中，3 个满足约定的九个标题及顺序。D 增量把 `### Blocked` 写成了 `## Blocked`，内容仍可读，但严格格式不符合。
- 所有输出中未发现输入外新编的完整 64 位十六进制引用或 callId。
- 两份增量摘要均仍有缩写引用。检查结果不能称为“全部准确”。
- Artifact ID 检查只验证完整性与是否来自输入；本轮没有执行 readArtifact，不再次验证存储内容与权限。

## 判断与下一步

保留 Pi 风格的结构有利于审阅和交接，但目前不存在“换一个 prompt 就保证准确”的证据。
建议优先考虑：重要 Artifact 引用由程序原样保留/注入；摘要提及的引用进行确定性校验；旧摘要中已损失的引用通过原始历史找回，找不到就明确不可用。
当前先记录这些边界，不自动增加数据库改造、不添加 Run 状态投影、不继续扩大模型调用次数。
下一轮若要测长期滚动，需要将**本轮新摘要**继续作为下一次输入，不能把本次旧摘要迁移样本当作其替代。
