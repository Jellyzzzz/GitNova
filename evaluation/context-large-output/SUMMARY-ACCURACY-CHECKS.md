# 摘要提示词验证口径

本次只改 ContextSummarizer 提示词，不添加 Run 最终状态投影，不改数据库或既有摘要。

## 固定输入与调用

- 重放 2026-09-20 多 Task 的 C/D 真实测试仓库记录，使用生产 SessionContextService 与 ContextSummarizer。
- 首次摘要：C 截止 sequence 34，D 截止 sequence 48。每份输入分别用旧/新提示词调用一次，源正文 SHA-256 必须相同。
- 增量摘要：保留档案中未经人工修正的旧摘要，合并其后 C 截止 67、D 截止 111 的实际记录，只测试新提示词。
- 总计最多 6 次请求，不自动重试，不以失败后重跑的方式挑选结果。
- 模型由 LLM_MODEL 配置，thinking disabled，输出上限 4096，总超时/读取超时各 60 秒。
- 与生产摘要请求一致，不设置 temperature，不执行工具。每份请求输入本地估计不得超过 26880。
- 这是固定历史的离线回放 + 真实摘要 API，不是 HTTP/Worker/数据库端到端测试。
- SQL 导出未包含 eventId，回放仅重建 Mapper 的因果关联键，模型可见的 payload 保持原样。

## 验证标准（在调用前确定）

1. 协议：STOP、无工具调用、非空正文；新提示词须有约定的九个标题并保持顺序。
2. 数值：保留首次 `BATCH SUMMARY cases=160 passed=153 failed=7` 与修复后 `160/160/0` 的时间区别，不把旧失败改为成功。
3. 根因与范围：保留折扣 HALF_UP、按折后金额判断免运费的规则及必要源码路径；区分当前任务和历史任务的允许写入范围。
4. 进度：首次摘要不能声称已经创建 EdgeRegression；增量 C 仍缺该文件；增量 D 已创建并实际运行 `EDGE SUMMARY cases=16 failed=0`。
5. 失败事实：增量 D 的故意失败路径 `cases=16 failed=1 / exit=1` 不能写成工作区当前回归失败。
6. 引用：输出的完整 artifactId 必须在输入中存在，不能新编或缩写；统计保留数量但不要求保留所有不再相关的引用。
7. 失真：检查 ORD-077 是否出现 `100×50/100=50.5` 错式；允许省略非必要算式，不允许新增错误计算。
8. 版本与信任：旧 generation 测试不能替代当前验证；模型自述不能升级为已验证事实；不推断整个 Run 的终止状态。
9. 任务连续性：保留当前任务必要的约束、未解决事项和下一步，不能只总结旧任务。

格式、字符串和引用集合做确定性检查；目标/时序/因果/遗漏逐项对照原始输入人工审阅。
不使用额外 LLM 作为正确性裁判，不把关键词命中率称为摘要整体准确率。
全部样本、失败、usage 和耗时原样保存；少量样本不能证明新提示词普遍优于旧提示词。
